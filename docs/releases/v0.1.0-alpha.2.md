# ShadowTalk v0.1.0-alpha.2 — bundled Tor

This alpha includes the Tor runtime in ShadowTalk's installers. Users no longer
need to install Tor separately; the application does not download executables
when it starts.

## Changes

- Installers and portable archives include Tor Expert Bundle 16.0.3 (Tor
  0.4.9.17), Lyrebird, their runtime libraries and license texts.
- ShadowTalk automatically finds its own Tor runtime after installation or
  relocation. Manual executable paths still take precedence.
- Direct connections need no Tor configuration file. For obfs4, the configuration
  can contain just mode, bridges and an optional timeout; Lyrebird is found
  automatically.
- The universal macOS app includes separate Apple Silicon and Intel Tor runtimes.
- Build downloads are pinned by SHA-256. Help, profile commands and chat startup
  perform no dependency downloads.

## Getting started

Download one installer for your OS and compare its SHA-256 with the attached
`checksums.txt`:

- **macOS:** use `shadowtalk_0.1.0-alpha.2_darwin_universal.dmg` for Apple Silicon
  or Intel. Drag **ShadowTalk.app → Applications**, open it and choose
  **3 — Команды** for CLI commands or **1 — Профиль** to create/open a profile.
- **Windows x64:** run the setup EXE and open a new terminal after installation.
- **Linux:** install the DEB or RPM matching your distribution and CPU.

Check `shadowtalk --version`; it should report `0.1.0-alpha.2`. Create a profile,
exchange invitations in both directions and run `shadowtalk chat` on both devices.
Direct Tor needs no executable paths or configuration file. Restricted networks
may need obfs4 bridges in `tor.json`; Lyrebird is included, but bridges are not
obtained automatically. Linux still needs an unlocked Secret Service collection
over a user D-Bus session.

See the [English](https://github.com/bacrehclb/ShadowTalk/blob/v0.1.0-alpha.2/README.md#usage)
and [Russian](https://github.com/bacrehclb/ShadowTalk/blob/v0.1.0-alpha.2/README.ru.md#использование)
walkthroughs. The macOS app opens Terminal; it is not a separate graphical chat client.

## Upgrading

Keep the existing profile and OS credential-store entry. To switch from an
alpha.1 configuration to bundled executables, remove `tor_binary` and
`lyrebird_binary` from `tor.json`, leaving bridge settings in place. No profile
or history migration is introduced. Existing explicit `--tor-binary` arguments
also keep their priority. See [bundled Tor](https://github.com/bacrehclb/ShadowTalk/blob/v0.1.0-alpha.2/docs/bundled-tor.md).

## Validation and limitations

The [Packages run on 2026-11-27](https://github.com/bacrehclb/ShadowTalk/actions/runs/45964087325)
passed for the bundled-Tor implementation at commit
`c8ae5725aa663865d1c43fda34f927d95ddf9828`:

- Linux amd64: DEB install/remove, installed CLI, Tor and Lyrebird execution.
- macOS: both architecture packages built, native package installation and
  bundled runtime execution on the runner.
- Windows amd64: EXE build, install/reinstall, bundled runtime execution, PATH
  handling and uninstall checks.
- Packaging tests, runtime integrity checks and final artifact collection passed.

This was a development snapshot. The tagged release pipeline separately runs Go
tests, vet and build on all three operating systems and rebuilds the packages.
Local macOS arm64 checks also exercised the real Tor controller and obfs4
transport handshake with external networking disabled. Linux arm64, the other
macOS architecture and native RPM installation are not established by the
native checks above. The custom DMG requires its own final payload check.

The earlier live Tor exchange report concerns two nodes on one macOS machine;
this release does not claim a completed two-computer test or independent security
audit. Signing remains ad-hoc on macOS; builds have no verified publisher signature.

Working bridges may still be needed on restricted networks. The OS credential
store is still required; Tor bundling does not replace it.
