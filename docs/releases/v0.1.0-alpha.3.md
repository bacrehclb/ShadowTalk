# ShadowTalk v0.1.0-alpha.3 — terminal menu

Release preparation; this version is not published yet.

The new menu brings profile setup, invitations, contacts and Tor settings into
one terminal interface. Existing CLI commands remain available for scripts.

## Changes

- Run `shadowtalk menu`, or just `shadowtalk` in a terminal. With redirected
  streams, the no-argument command still prints help. The macOS app opens the menu.
- Create an invitation with a chosen lifetime, copy its token/fingerprint or save
  a new file. Copy uses the native clipboard on macOS and OSC 52 on other terminals;
  file export is the fallback. Existing files are not overwritten.
- Import a pasted token or invitation file, review the identity and confirm the
  full fingerprint from the other participant. Key changes are never auto-accepted.
- Select a saved contact to open chat, or explicitly confirm local removal.
- Choose direct Tor or obfs4, paste multiple bridge lines, set the startup timeout
  and optionally choose custom Tor/Lyrebird executables. The menu validates and
  saves `tor.json`; no manual JSON editing or chmod is needed.
- Configuration writes reject stale edits and preserve malformed/unsupported
  files. On Unix new configuration files have mode 0600. Esc cancels an unfinished
  form; quitting during a write waits for completion.

## Upgrade and use

Keep the existing profile and OS credential-store keys. Identity, contacts,
history and Tor paths are unchanged; no data migration is required. Existing
explicit Tor/Lyrebird paths stay active. Leave those fields empty to select the
bundled runtimes automatically. The interface is currently in Russian and needs
a terminal of at least 60 × 20.

Both participants must import each other and have chat running for delivery.
Settings apply when chat next opens. Bridge acquisition is still manual through
Tor Project; the menu automates validation and storage, not CAPTCHA or delivery
of new bridges. A valid bridge string does not establish that its endpoint works.

## Validation and release status

Local macOS arm64 checks passed: `go test -race ./...`, `go vet ./...`, and
`go build ./...`. A PTY test exercises menu navigation, profile creation,
invitation export and Tor settings. The universal development app was built
locally with bundled Tor and an ad-hoc signature. This change does not
establish a live macOS-to-container exchange or independent-machine testing.
Native Windows and Linux menu tests have not been run for this version.
The existing alpha limitations, lack of an independent security audit, and macOS
ad-hoc signing remain applicable. Final installer verification and publication
are separate steps after committing the source.
