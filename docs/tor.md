# Транспорт Tor

Модуль `internal/transport/tor` готовит сетевой поток для `securechannel`.
`peers` связывает транспорт с подтверждёнными контактами, TLS и лимитами.
`chat` добавляет живые диалоги и события приёма; `app.PeerSessions.StartChat`
запускает их поверх той же конфигурации профиля и Tor.
CLI поддерживает локальные приглашения и контакты. Команда `shadowtalk chat`
запускает Tor, историю и доставку через `app.PeerSessions.StartDelivery`.

## Зависимость времени выполнения

Запуск интерфейса: `shadowtalk chat --contact alice`. Сборки для alpha.2 содержат
Tor и Lyrebird; CLI находит их относительно своего исполняемого файла через
`internal/torbundle`. Для своего Tor укажите `--tor-binary PATH`.
`--startup-timeout` по умолчанию 3 минуты, допустимы
значения от 1 секунды до 15 минут. Во время запуска Esc/Ctrl+C отменяет операцию
и дожидается очистки. Данные Tor находятся в `tor` внутри каталога профиля.

Опубликованная alpha.1 и сборки без комплекта используют отдельный Tor
с поддержкой onion v3 и SAFECOOKIE. Для них используйте стабильную версию из
[официальных сборок Tor Project](https://www.torproject.org/download/tor/)
или доверенного пакетного менеджера ОС. Библиотеки из Expert Bundle должны
оставаться рядом с бинарником согласно структуре дистрибутива.
Tor скачивается и проверяется при сборке пакетов; запуск чата не выполняет
загрузок и не подключается к работающему Tor Browser или системной службе.
Расположение файлов, подписи и обновление версии описаны в
[поставке Tor](bundled-tor.md).

## Конфигурация подключения

`chat` читает `tor.json` внутри каталога профиля. Для другого файла:

```sh
shadowtalk chat --tor-config "/path/to/tor.json"
```

Начиная с исходников alpha.3 файл можно создать и изменить через
`shadowtalk menu` → **Настройки Tor и мосты**. Меню принимает список мостов,
тайм-аут и необязательные абсолютные пути программ, проверяет значения и
сохраняет файл с правами 0600 на Unix. Запись идёт через временный файл и rename;
`.tor-config.lock` координирует сохранения. Если настройки изменились после открытия
формы, нужна повторная загрузка; повреждённые файлы автоматически не заменяются.
Esc отменяет редактирование. Получение мостов у Tor Project пока ручное.

При ручном редактировании пример прямого подключения:

```json
{
  "version": 1,
  "mode": "direct",
  "startup_timeout": "5m"
}
```

Tor будет выбран из комплекта, а при отсутствии комплекта — из PATH.
Чтобы сохранить конкретный бинарник, добавьте
`"tor_binary": "/absolute/path/to/tor"`. Любые относительные пути **в JSON**
считаются от каталога этого JSON, а путь во флаге `--tor-binary` — от текущей cwd.
На Windows в JSON используйте двойной обратный слеш (`C:\\Tor\\tor.exe`) или `/`.

Для obfs4 нужны рабочие строки мостов, полученные через Tor Project.
В сборках для alpha.2 Lyrebird уже включён. В примере замените строку-заполнитель
на рабочую; `tor_binary` и `lyrebird_binary` нужны только для своих программ
или старой alpha.1:

```json
{
  "version": 1,
  "mode": "obfs4",
  "startup_timeout": "5m",
  "bridges": [
    "obfs4 IP:PORT FINGERPRINT cert=CERTIFICATE iat-mode=0"
  ]
}
```

Поддерживается от 1 до 16 полных строк `obfs4 IP:PORT FINGERPRINT cert=... iat-mode=...`;
IPv6 записывается как `[ADDRESS]:PORT`, fingerprint — 40 hex-символов,
cert — unpadded Base64 от 52 байт, iat-mode — 0, 1 или 2. Строку из источника
нужно сохранить целиком. Имена хостов, произвольные директивы torrc, дополнительные
аргументы и другие транспорты пока не поддерживаются.

На macOS/Linux ограничьте доступ к файлу:

```sh
chmod 600 "/path/to/tor.json"
```

На Windows файл защищается ACL учётной записи. `tor.json` содержит адреса мостов
открытым текстом, поэтому не публикуйте его; имя добавлено в `.gitignore`.
Для файла с другим именем исключение нужно задать самостоятельно.

Приоритет пути Tor: явный `--tor-binary` → JSON → комплект → PATH.
Lyrebird выбирается по `lyrebird_binary`, затем из комплекта или PATH.
Отсутствующий комплект допускает PATH, повреждённый комплект останавливает запуск.
Приоритет тайм-аута: `--startup-timeout` → JSON → 3 минуты.
Файл ограничен 16 KiB; неизвестные или повторные поля, `null`, неподдерживаемая
версия, ссылки и небезопасные Unix-права отклоняются. Нет файла по умолчанию —
обычный прямой Tor. Нет явно указанного файла или есть ошибка существующего —
запуск прекращается до открытия профиля и базы. Флаги не обходят проверку файла.
Выбранный obfs4 не переключается автоматически на прямое подключение.
Enter / `r` после ошибки перечитывает настройки, поэтому их можно исправить
в редакторе и повторить запуск. Работающий чат применит изменения после перезапуска.

ShadowTalk запускает Lyrebird через точный путь без shell, ожидает управляемый
PT-протокол версии 1 и loopback SOCKS5, затем передаёт этот порт Tor. При выходе
сначала останавливает Tor, затем закрывает stdin Lyrebird; зависший процесс
принудительно завершается после `ShutdownTimeout`. Неожиданный выход Lyrebird
останавливает узел. Его временные данные удаляются вместе с каталогом запуска.

TUI показывает процент и этап из Tor: транспорт, соединение с ретранслятором,
рукопожатие, каталог сети, цепочка, публикация службы. 100% bootstrap ещё не
означает готовность onion-службы: приложение отдельно ждёт её публикации.
Неизвестный тег отображается общим этапом. Ошибка сохраняет последний процент
и известную категорию проблемы; исходные WARNING/SUMMARY, адреса мостов и ключи
не попадают в интерфейс.

## API и время жизни

```go
node, err := tor.Start(lifetimeContext, loaded.Keys, tor.Options{
    BinaryPath: "/absolute/path/to/tor", // пустое значение ищет tor в PATH
    DataDir: filepath.Join(profileDirectory, "tor"),
})
if err != nil {
    return err
}
defer node.Close()

raw, err := node.Dial(connectContext, peerOnionAddress)
if err != nil {
    return err
}
connection, err := endpoint.Client(connectContext, raw, trustedPeerPublicKey)
if err != nil {
    return err // securechannel уже закрыл raw
}
defer connection.Close()
```

Для входящего соединения вызываются `node.Accept()` и `endpoint.Server()`.
Ожидаемый ключ должен быть получен из подтверждённого контакта или будущей
процедуры знакомства. Сам onion-адрес не подтверждает личность собеседника.

Для сценариев приложения используйте `app.PeerSessions`, чтобы управление
входящими потоками, проверка ключей и очистка оставались в одном месте:

```go
// profiles — app.Profiles, profile — ранее прочитанные публичные метаданные.
service := app.NewPeerSessions(
    profiles,
    contactsfile.New(profileDirectory, profile.PublicKey),
    func(ctx context.Context, keys identity.KeyPair) (peers.Transport, error) {
        return tor.Start(ctx, keys, tor.Options{
            BinaryPath: torBinary,
            DataDir: filepath.Join(profileDirectory, "tor"),
        })
    },
)
manager, err := service.Start(lifetimeContext, peers.Options{})
if err != nil {
    return err
}
defer manager.Close()
session, err := manager.Connect(connectContext, "alice")
if err != nil {
    return err
}
defer session.Close()
// Для входящих: manager.Accept(waitContext).
// Дедлайны и протокол последующего I/O задаёт вызывающий код.
```

Оба участника заранее сохраняют контакты. Изменения книги применяются после
перезапуска менеджера. Подробности — [ADR 0008](decisions/0008-peer-sessions.md).

`Start` ожидает bootstrap и событие успешной загрузки дескриптора своей службы.
Это подтверждает публикацию, но не гарантирует доступность из любой точки сети.
Отмена `lifetimeContext` останавливает весь узел даже после успешного запуска.
Отмена контекста `Dial` после его успешного завершения не закрывает поток.
Чтение и запись после подключения ограничиваются дедлайнами самого `net.Conn`.

| Параметр | По умолчанию |
| --- | --- |
| `StartTimeout` | 3 минуты на запуск, bootstrap и публикацию |
| `DialTimeout` | 1 минута на TCP + SOCKS5 + onion-connect |
| `ShutdownTimeout` | 5 секунд до принудительного завершения Tor |

Более ранний дедлайн контекста имеет приоритет. Отрицательные значения отклоняются.
`Accept` прерывается закрытием узла; исходящие и принятые соединения также закрываются.
`Done()` закрывается после очистки, `Err()` сообщает причину незапрошенной остановки.
Повторные и одновременные `Close()` безопасны.

## Каталог и адрес

`DataDir` обязателен и должен быть выделен только этому экземпляру ShadowTalk.
На Unix нужен режим `0700`; существующий общий каталог не исправляется автоматически.
Межпроцессная блокировка `.shadowtalk.lock` запрещает два узла с одним каталогом.
Файл блокировки после выхода может остаться — он не означает активную блокировку.

В каталоге сохраняются guard state и кэш Tor. Временная `.shadowtalk-run-*`
содержит управляемый torrc, cookie и адрес ControlPort; в режиме obfs4 там также
находятся временные данные Lyrebird. Каталог удаляется после остановки.
После принудительного убийства самого приложения старый временный каталог может
остаться, но новый запуск не использует его cookie. Не храните runtime-данные в Git.

Onion-ключ не записывается отдельным открытым файлом. Он детерминированно выводится
из seed профиля через HKDF; Tor получает его через аутентифицированный ControlPort.
Адрес сохраняется при перезапуске и восстановлении той же идентичности. Новый профиль
получает другой адрес. Копия одного профиля на двух устройствах одновременно
публикует одну службу — многопользовательская синхронизация копий не поддерживается.

## Ошибки и проверки

**Актуальный сетевой результат:** 25 ноября 2026 `TestTorSecureChannelLive`
полностью прошёл через obfs4 на macOS arm64: два узла, сообщения в обе стороны,
ACK, сохранение истории и автоматическая доставка очереди после перезапуска.
Длительность — 63,78 секунды. Оба узла находились на одном компьютере;
другие устройства и платформы этим запуском не проверялись.
Условия и воспроизводимая команда — в [отчёте](testing/tor-live-exchange.md).

Ошибки различаются через `errors.Is`: недоступный бинарник, занятый или небезопасный
каталог, отказ SAFECOOKIE, отказ контроллера, неверный адрес, отказ подключения,
выход процесса и ошибки контекста. Исходные control-ответы и логи Tor не выдаются,
поскольку могут содержать onion-ключ и адреса. Прямого соединения при отказе Tor нет.
Повторами подключения управляет `delivery` с постоянной очередью и задержками.
Поддерживаются явно заданные мосты obfs4; их получение и обновление выполняет
пользователь. Автоматический подбор мостов пока не реализован.

Обычные тесты используют протокольный подставной процесс. Сквозной сценарий
`TestTorDeliveryRestart` запускает два таких процесса через тот же
`app.PeerSessions.StartDelivery`, который использует CLI. Он проверяет:

- двусторонний обмен через SOCKS5 и TLS с сохранением текста в SQLite и ACK;
- постановку сообщения в очередь после выключения получателя;
- сохранение pending-записи и счётчика попыток при остановке отправителя;
- перезапуск обоих узлов с прежними зашифрованными seed, контактами и onion-адресами;
- автоматическую доставку прежнего ID без повторного вызова `Queue` и без дублей;
- сохранение статуса delivered после закрытия и повторного открытия SQLite;
- освобождение хранилищ и очистку временных каталогов Tor.

`TestTorSecureChannelLive` выполняет тот же сценарий с настоящим бинарником Tor
и обычными настройками доставки. Каждый запуск Tor по умолчанию ограничен 3 минутами,
весь сценарий — 12 минутами. После перезапуска повторная попытка может ждать
сохранённого срока восстановления очереди; тест не меняет его вручную.
Идентичности, сообщения и каталоги временные, хранилище секретов ОС не используется.
Оба узла работают на одной машине: это не проверка всех сетей и платформ.
Команды приведены в [README](../README.md#development). Сетевой тест включается
явно и зависит от доступности Tor. Успех локального сценария и кросс-компиляции
не заменяет проверки публичной сети и запуска на целевых ОС.

Дополнительный PTY-тест команды `chat` запускает два настоящих CLI с подставными
Tor-процессами: проверяет ввод, TLS, доставку, SQLite, статусы ACK, перезапуск,
отмену запуска и восстановление терминала. Этот тест не обращается к публичной сети.

## История проверок

Ниже сохранены результаты предыдущих этапов. Их ограничения относятся к моменту
конкретного запуска; актуальный успешный результат приведён выше.

Проверка 22 ноября 2026 на macOS arm64: тесты проекта с race detector и `go vet`
прошли, тестовый пакет транспорта скомпилирован для Windows/Linux amd64.
Tor 0.4.9.16 подтвердил SAFECOOKIE и совпадение onion-ключа/адреса в локальном тесте.
Попытка реального обмена завершилась через 3 минуты: оба процесса остались на
bootstrap 10%. Обмен через публичную сеть в этой среде пока не подтверждён;
его нужно повторить в окружении с работающим подключением к Tor.

Повторная проверка 24 ноября 2026 на macOS arm64 с Tor 0.4.9.16:
локальный сценарий доставки и перезапуска, полный набор `go test -race ./...`,
`go vet ./...`, `go build ./...` и `TestNativeTorControl` прошли. Новый
интеграционный пакет также скомпилирован для Windows/Linux amd64;
это не запуск тестов на этих ОС.

Публичный `TestTorSecureChannelLive` остановился через 180 секунд: оба узла
сообщили `Tor bootstrap (14%): context deadline exceeded`. До обмена текстом
сценарий не дошёл. Отдельный запуск того же бинарника без кода ShadowTalk,
с пустым torrc и новым временным каталогом, за 90 секунд дошёл до
`10% (conn_done)` и сообщил предупреждения, связанные с TLS/handshake.
Процесс был остановлен, временные данные удалены.

В текущей [спецификации Tor](https://spec.torproject.org/control-spec/implementation-notes.html)
`conn_done` означает установление соединения с ретранслятором, а `handshake`
на 14% — его TLS-рукопожатие. Это соединение самого Tor, которое предшествует
защищённому диалогу ShadowTalk. Независимая проверка указывает на проблему
подключения Tor в этом окружении, но не устанавливает её причину: блокировку,
настройки сети или другую неисправность. На тот момент публичная доставка
и восстановление очереди через Tor ещё не были подтверждены.

Модуль конфигурации дополнительно проверен на macOS arm64: PTY-сценарий читает
сохранённый конфиг, показывает 14% и безопасную ошибку, перечитывает исправленный
файл и запускает obfs4 с тестовыми процессами. Настоящие Tor 0.4.9.16 и Lyrebird
прошли `TestNativeObfs4Control`: PT-handshake, SAFECOOKIE и подтверждение настроек
через GETCONF при `DisableNetwork=1`. Это не проверка доступности моста или доставки
через него. Для неё задайте `SHADOWTALK_TOR_CONFIG=/path/to/tor.json` при запуске
`TestTorSecureChannelLive`; тест использует временные профили и покажет только
числовые стадии, проценты и категории проблем. Рабочий мост для такого запуска
в этой проверке не предоставлялся.
