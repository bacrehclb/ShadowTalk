# Транспорт Tor

Модуль `internal/transport/tor` готовит сетевой поток для `securechannel`.
`peers` связывает транспорт с подтверждёнными контактами, TLS и лимитами.
CLI уже поддерживает локальные приглашения и контакты, но ни одна команда
пока не запускает Tor. Экран чата остаётся следующим этапом.

## Зависимость времени выполнения

Нужен отдельный исполняемый файл Tor с поддержкой onion v3 и SAFECOOKIE.
Используйте актуальную стабильную версию из
[официальных сборок Tor Project](https://www.torproject.org/download/tor/)
или доверенного пакетного менеджера ОС. Библиотеки из Expert Bundle должны
оставаться рядом с бинарником согласно структуре дистрибутива.
Приложение не скачивает Tor автоматически и не подключается к работающему
Tor Browser или системной службе. Упаковка Tor в релиз — отдельная задача.

## API и время жизни

```go
node, err := tor.Start(lifetimeContext, loaded.Keys, tor.Options{
    BinaryPath: "/absolute/path/to/tor", // пустое значение ищет tor в PATH
    DataDir: filepath.Join(profileDirectory, "tor"),
})
if err != nil {
    return err
}
defer node.Close()

raw, err := node.Dial(connectContext, peerOnionAddress)
if err != nil {
    return err
}
connection, err := endpoint.Client(connectContext, raw, trustedPeerPublicKey)
if err != nil {
    return err // securechannel уже закрыл raw
}
defer connection.Close()
```

Для входящего соединения вызываются `node.Accept()` и `endpoint.Server()`.
Ожидаемый ключ должен быть получен из подтверждённого контакта или будущей
процедуры знакомства. Сам onion-адрес не подтверждает личность собеседника.

Для сценариев приложения используйте `app.PeerSessions`, чтобы управление
входящими потоками, проверка ключей и очистка оставались в одном месте:

```go
// profiles — app.Profiles, profile — ранее прочитанные публичные метаданные.
service := app.NewPeerSessions(
    profiles,
    contactsfile.New(profileDirectory, profile.PublicKey),
    func(ctx context.Context, keys identity.KeyPair) (peers.Transport, error) {
        return tor.Start(ctx, keys, tor.Options{
            BinaryPath: torBinary,
            DataDir: filepath.Join(profileDirectory, "tor"),
        })
    },
)
manager, err := service.Start(lifetimeContext, peers.Options{})
if err != nil {
    return err
}
defer manager.Close()
session, err := manager.Connect(connectContext, "alice")
if err != nil {
    return err
}
defer session.Close()
// Для входящих: manager.Accept(waitContext).
// Дедлайны и протокол последующего I/O задаёт вызывающий код.
```

Оба участника заранее сохраняют контакты. Изменения книги применяются после
перезапуска менеджера. Подробности — [ADR 0008](decisions/0008-peer-sessions.md).

`Start` ожидает bootstrap и событие успешной загрузки дескриптора своей службы.
Это подтверждает публикацию, но не гарантирует доступность из любой точки сети.
Отмена `lifetimeContext` останавливает весь узел даже после успешного запуска.
Отмена контекста `Dial` после его успешного завершения не закрывает поток.
Чтение и запись после подключения ограничиваются дедлайнами самого `net.Conn`.

| Параметр | По умолчанию |
| --- | --- |
| `StartTimeout` | 3 минуты на запуск, bootstrap и публикацию |
| `DialTimeout` | 1 минута на TCP + SOCKS5 + onion-connect |
| `ShutdownTimeout` | 5 секунд до принудительного завершения Tor |

Более ранний дедлайн контекста имеет приоритет. Отрицательные значения отклоняются.
`Accept` прерывается закрытием узла; исходящие и принятые соединения также закрываются.
`Done()` закрывается после очистки, `Err()` сообщает причину незапрошенной остановки.
Повторные и одновременные `Close()` безопасны.

## Каталог и адрес

`DataDir` обязателен и должен быть выделен только этому экземпляру ShadowTalk.
На Unix нужен режим `0700`; существующий общий каталог не исправляется автоматически.
Межпроцессная блокировка `.shadowtalk.lock` запрещает два узла с одним каталогом.
Файл блокировки после выхода может остаться — он не означает активную блокировку.

В каталоге сохраняются guard state и кэш Tor. Временная `.shadowtalk-run-*`
содержит пустой torrc, cookie и адрес ControlPort; она удаляется после остановки.
После принудительного убийства самого приложения старый временный каталог может
остаться, но новый запуск не использует его cookie. Не храните runtime-данные в Git.

Onion-ключ не записывается отдельным открытым файлом. Он детерминированно выводится
из seed профиля через HKDF; Tor получает его через аутентифицированный ControlPort.
Адрес сохраняется при перезапуске и восстановлении той же идентичности. Новый профиль
получает другой адрес. Копия одного профиля на двух устройствах одновременно
публикует одну службу — многопользовательская синхронизация копий не поддерживается.

## Ошибки и проверки

Ошибки различаются через `errors.Is`: недоступный бинарник, занятый или небезопасный
каталог, отказ SAFECOOKIE, отказ контроллера, неверный адрес, отказ подключения,
выход процесса и ошибки контекста. Исходные control-ответы и логи Tor не выдаются,
поскольку могут содержать onion-ключ и адреса. Прямого соединения при отказе Tor нет.
Повторы подключения остаются ответственностью будущего сценария чата/доставки.
Мосты и pluggable transports пока не настраиваются.

Обычные тесты используют протокольный подставной процесс. Сквозной тест передаёт
кадры текста и ACK через `peers`, TLS и два таких процесса; постоянное сохранение
сообщений этим тестом не проверяется. Команды проверок на настоящем Tor,
включая обмен кадрами двух узлов через TLS, приведены в
[README](../README.md#разработка). Сетевой тест включается явно и зависит от
доступности Tor. Кросс-компиляция не заменяет такие проверки на целевых ОС.

Проверка 22 ноября 2026 на macOS arm64: тесты проекта с race detector и `go vet`
прошли, тестовый пакет транспорта скомпилирован для Windows/Linux amd64.
Tor 0.4.9.16 подтвердил SAFECOOKIE и совпадение onion-ключа/адреса в локальном тесте.
Попытка реального обмена завершилась через 3 минуты: оба процесса остались на
bootstrap 10%. Обмен через публичную сеть в этой среде пока не подтверждён;
его нужно повторить в окружении с работающим подключением к Tor.
