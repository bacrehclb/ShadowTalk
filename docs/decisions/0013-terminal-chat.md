# ADR 0013: терминальный чат поверх доставки

Статус: принято.

## Контракт команды

`shadowtalk [--profile-dir PATH] chat [--contact NAME] [--tor-binary PATH]
[--startup-timeout 3m]` открывает полноэкранную переписку. Нужны существующая
идентичность, доступное хранилище ключей ОС и отдельный Tor. По умолчанию `tor`
ищется в PATH; относительные пути считаются от cwd. Время запуска — от 1 секунды
до 15 минут. Команда не скачивает Tor, не изменяет PATH и не использует Tor Browser.

`chat --help` работает без ключей, каталога профиля и сети. Неверные параметры
отклоняются до запуска. Нужны терминальные stdin и stdout; pipe и `TERM=dumb`
отклоняются без чтения профиля. Успех/ручной выход возвращает 0, ошибки — 1.
Диагностика выводится в stderr после восстановления терминала. `NO_COLOR`
отключает цвет. Команды `ui`, `profile`, `invite`, `contacts` сохраняют прежний
контракт; `ui` по-прежнему управляет профилем, не запускает сеть самостоятельно.

Чат использует `messages.db` и каталог `tor` внутри профиля. При открытии могут
выполняться миграция базы, запись истории/очереди и запуск собственного процесса
Tor. После готовности транспорта автоматически возобновляется сохранённая очередь.
Сначала выполняются загрузка профиля/контактов, открытие истории, запуск Tor.
Экран показывает реальные этапы и прошедшее время, без вымышленных процентов.
История доступна после успешного запуска Tor; отдельного офлайн-просмотра пока нет.

## Разделение ответственности

`cmd/shadowtalk/chat_cli.go` разбирает флаги, собирает `app.PeerSessions.StartDelivery`
со SQLite и Tor и адаптирует доставку к интерфейсу `tui.ChatSession`. Модель экрана
получает только публичный профиль, контакты, сообщения и статусы. Приватные ключи
не возвращаются в сообщения Bubble Tea. Сеть и SQL остаются за адаптером.

- `chat_runtime.go` управляет запуском, асинхронными запросами и завершением;
- `chat.go` хранит состояние экрана и обрабатывает клавиатуру;
- `chat_view.go` формирует экран и безопасное представление текста;
- `chat_run.go` проверяет терминал, запускает Bubble Tea и гарантирует очистку
  также при ошибке самого терминального цикла.

Runtime регистрирует выполняющиеся команды, отменяет их при выходе и ждёт
завершения перед закрытием сессии. Успешный запуск, пришедший после отмены,
тоже закрывается. Esc/Ctrl+C и внешние SIGINT/SIGTERM проходят через один путь
завершения; UI не завершает процесс поверх активной записи. Уже начатая операция
системного хранилища ключей может потребовать дождаться системного диалога.

## Экран и ввод

Минимальный размер — 60 × 20. Слева контакты, справа история, снизу поле сообщения.
При уменьшении окна скрытые действия отправки блокируются, черновик сохраняется.
Размер возвращается — отображается прежний ввод.

| Клавиша | Действие |
| --- | --- |
| Tab / Shift+Tab | Контакты или ввод |
| ↑ / ↓ в списке | Выбор контакта |
| Ctrl+N / Ctrl+P | Следующий / предыдущий контакт |
| Enter в списке | Перейти к вводу |
| Enter при вводе | Сохранить сообщение в очередь |
| Alt+Enter | Новая строка (также Ctrl+J, если терминал его различает) |
| PgUp / PgDn | Прокрутка истории; PgUp вверху загружает более старую страницу |
| Ctrl+L | Последняя страница и актуальные статусы |
| Ctrl+R после ошибки записи | Повторить сохранение с прежним ID |
| Esc / Ctrl+C | Остановить чат и выйти |

Отправка асинхронна, повторный Enter во время сохранения игнорируется. После
ошибки текст и ID сохраняются, редактирование этой попытки блокируется: повтор
использует тот же ID и текст, а не создаёт потенциальный дубль. Другие диалоги
доступны. Черновики разных контактов сохраняются в памяти; при выходе несохранённый
ввод теряется. Уже подтверждённая локальная запись остаётся в очереди после выхода.

Вставка с переводами строк не отправляет текст автоматически. Если она превышает
лимит 16384 байта UTF-8, вся вставка отклоняется с объяснением, без молчаливого
усечения. Счётчик показывает байты. ID создаётся один раз перед первым сохранением.

## История, статусы и обновления

Чтение идёт страницами по 50 записей, в памяти текущего диалога — не больше 200.
При загрузке более старых страниц самые новые записи удаляются только из
представления, не из базы. Ctrl+L возвращает последние 50. Запрос предыдущего
диалога отменяется; поколение запроса не позволяет позднему ответу подменить
историю выбранного контакта.

`delivery.Changes` остаётся объединённым уведомлением. Дополнительный `Activity`
возвращает отдельный снимок счётчиков изменений по проверенным ключам. Метка `•`
указывает изменения у другого контакта с момента просмотра в этом запуске.
Это не постоянный счётчик непрочитанных и не read receipt. Карта ограничена
снимком контактов; в уведомления не копируется текст сообщений.

В конце последней страницы новые изменения обновляют экран автоматически.
При просмотре старой истории показывается подсказка Ctrl+L. Исходящие показывают
«ожидает доставки» или «доставлено»; старые записи без outbox — «сохранено (старое)»,
без придуманного статуса. Часы в истории — UTC. «Tor готов» означает готовность
локального транспорта, не присутствие каждого собеседника онлайн. Подключение
к контакту выполняется слоем доставки при отправке. Контакты обновляются после
перезапуска чата, управление приглашениями остаётся в существующих командах.

## Безопасный терминальный вывод

Перед стилями и переносами строк текст проходит очистку: ESC, C0/C1, bidi и прочие
форматирующие управляющие символы заменяются видимым `�`; LF сохраняется,
табуляция отображается пробелами. ZWJ/ZWNJ сохраняются для обычного письма и emoji.
Каждая строка тела отделена от заголовка сообщения. Входящая запись в базе
не изменяется; очищается только представление. Вставляемый в редактор текст
проходит ту же проверку до отображения и отправки. OSC 52, очистка экрана,
возврат каретки и подмена направления через bidi-контроли не исполняются.

Ошибки драйвера и Tor не выводятся как произвольный текст: CLI сопоставляет
известные причины с подсказками. Для неизвестной ошибки используется общий текст.
Полные токены, ключи и содержимое переписки не входят в диагностику.

## Проверки и пределы

Модель проверяется на повтор Enter, неизменность ID при ошибке, сохранение
черновиков, поздние ответы, предел страниц, изменение размера и управляющие
последовательности. Проверки настоящего дочернего CLI включают help, ошибочные
флаги, pipe и отказ без побочных эффектов.

PTY-тест для macOS/Linux запускает два CLI, два подставных процесса Tor с
SAFECOOKIE/SOCKS, настоящий TLS и SQLite: ввод, отправку, ACK, обратный ответ,
перезапуск и загрузку истории. Проверяются NO_COLOR, восстановление termios,
отмена запуска и освобождение файлов/блокировок. Windows требует отдельной
ручной проверки интерактивного терминала; кросс-компиляция её не заменяет.
Обмен через публичный Tor всё ещё нужно подтвердить отдельно.
