# 0006. Отдельный процесс Tor и стабильная onion-служба

Статус: принято.

## Контекст

ShadowTalk нужен P2P-поток без общего сервера и без открытия входящего порта на
роутере пользователя. `securechannel` уже проверяет точные ключи профилей,
но не открывает соединения. Адрес для приглашений должен переживать перезапуск.

## Решение

`transport/tor` владеет отдельным процессом Tor, приватным каталогом runtime,
блокировкой постоянного каталога данных и всеми выданными соединениями.
Входящий поток приходит через v3 onion-службу на локальный случайный порт.
Исходящий поток проходит через собственный loopback SOCKS5; допустимы только
проверенные v3 onion-имена и виртуальный порт 443. Direct/DNS fallback отсутствует.

Служба использует отдельный Ed25519 seed: HKDF-SHA256 от 32-байтового seed профиля,
пустая salt, info `ShadowTalk/onion-service/v1`, длина 32 байта. Это стабильный
формат идентичности. Tor получает expanded Ed25519 key (SHA-512 seed с clamping),
а не формат приватного ключа Go. Onion-адрес вычисляется по спецификации v3
через публичный ключ, SHA3-256 checksum и байт версии 3. Векторы закреплены тестами;
отдельный тест проверяет совпадение адреса с ответом настоящего Tor.

ControlPort требует SAFECOOKIE. Используется `bine/control` для протокола и
аутентификации, но жизненный цикл процесса и отменяемый SOCKS5 реализованы
отдельно: `x/net/proxy.ContextDialer` ограничивает также SOCKS-handshake.
Высокоуровневые `bine/tor` и его dialer не используются. Зависимости зафиксированы;
старая версия bine требует повторного рассмотрения при изменении control-протокола.

`ADD_ONION` вызывается с `DiscardPK`, без `Detach`; ответ сверяется с ожидаемым
адресом. До настройки сеть отключена. После `SETCONF DisableNetwork=0` запрашивается
SOCKS-порт (при отключённой сети Tor его не открывает). `Start` ждёт bootstrap 100%
и `HS_DESC UPLOADED` именно своей службы, затем снимает подписку.

`TAKEOWNERSHIP` привязывает процесс к контроллеру, а `__OwningControllerProcess`
прикрывает раннее аварийное завершение приложения. Закрытие узла закрывает потоки
и контроллер, ожидает Tor, при превышении лимита убивает и дожидается процесса,
удаляет собственный runtime-каталог и освобождает блокировку. Guard state сохраняется.

## Последствия и ограничения

- Пользовательский интерфейс и контакты остаются независимыми от запуска Tor.
  Поток обязательно проходит через `securechannel` до сообщений приложения.
- Отдельного открытого onion-ключа на диске нет. Восстановление профиля сохраняет
  адрес; стабильный адрес позволяет связывать сеансы. Ротация адреса потребует
  нового явного решения о состоянии и версии derivation.
- Общего сервера ShadowTalk нет; работа зависит от публичной сети Tor.
  Публикация дескриптора не гарантирует немедленную доступность всем клиентам.
- Tor нужен как внешний runtime. Установка, обновление, упаковка, мосты,
  ограничения входящих запросов и пользовательская диагностика — отдельные этапы.
- Подставные тесты покрывают протокол и сбои без интернета. Опциональные проверки
  настоящего бинарника и реальной сети не заменяются подставным процессом.
