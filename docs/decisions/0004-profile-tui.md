# 0004 Терминальный интерфейс локального профиля

Статус: реализовано.

## Решение

Добавлена явная команда `shadowtalk [--profile-dir PATH] ui` на
[Bubble Tea v2](https://pkg.go.dev/charm.land/bubbletea/v2@v2.1.2), с компонентом
ввода Bubbles и оформлением Lip Gloss. Без аргументов приложение по-прежнему
показывает справку; контракты команд `profile` не меняются.

TUI проверяет stdin и stdout независимо до чтения профиля. Перенаправленный
поток и `TERM=dumb` означают отказ с кодом 1 без изменения данных. Программа
не открывает другой терминал вместо перенаправленного stdin. stderr может
быть перенаправлен отдельно. `NO_COLOR` отключает цвета, но не управление
курсорным и полноэкранным режимами.

Экран определяется чтением: новый профиль, готовая идентичность, старый профиль
без ключей, незавершённое создание либо ошибка. Запись начинается только по
Enter. После неопределённого исхода команда перечитывает состояние вместо
автоматического повторения записи. Потерянный ключ не превращает существующий
профиль в форму создания нового.

## Границы и завершение

Интерфейс `tui.Profiles` возвращает публичные метаданные, а не `app.LoadedProfile`.
Адаптер в `cmd/shadowtalk` отделяет приватные ключи от модели экрана. TUI не
работает с файловой системой или хранилищем ОС напрямую. Пути и диагностика
очищаются от управляющих символов перед выводом в терминал.

Операции выполняются через `tea.Cmd` вне цикла обработки клавиш. Одновременно
разрешена одна операция. Esc/Ctrl+C во время операции запрашивает выход после
её завершения; окно продолжает обрабатывать изменение размера. Системный
диалог хранилища ОС может требовать разрешения или отказа пользователя.
Принудительное завершение процесса остаётся случаем восстановления по ADR 0003.

Обычный выход имеет код 0; выход с неустранённой ошибкой профиля — код 1 и
диагностику после возврата из полноэкранного режима. Проверка неверного ника
остаётся ошибкой формы и не вызывает запись. Минимальное окно — 40 × 20;
при меньшем размере показана подсказка, действие Enter отключено, выход доступен.

## Проверки

Тесты модели проверяют валидацию, переходы после ошибок, подтверждение обновления
и восстановления, повторный Enter, ожидание операции при выходе и resize.
Тесты CLI проверяют справку, неизвестные аргументы и запуск с pipe без изменений.

На macOS и Linux PTY-тесты запускают отдельный процесс с тестовым хранилищем
ключей. Они проверяют создание, повторную загрузку, обновление, восстановление
после аварии, клавиатуру, resize, `NO_COLOR`, отказ для `TERM=dumb` и
перенаправленных потоков. Режим терминала сравнивается в дочернем процессе
до и после TUI, пока macOS ещё не отозвала его PTY. Тестовые адаптеры отсутствуют
в рабочем бинарнике. На Windows запускаются тесты модели и обычного процесса;
интерактивный Windows-терминал требует отдельной проверки.
