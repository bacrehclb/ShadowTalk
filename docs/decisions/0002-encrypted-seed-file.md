# 0002 Файл зашифрованного seed

Статус: принято для адаптера хранения; подключение к профилю — следующий этап.

## Решение

`storage/seedfile` хранит один файл `identity-seed.json` в переданном каталоге.
Относительный путь считается от рабочей директории процесса. Формат — UTF-8 JSON:

| Поле | Содержание |
| --- | --- |
| `version` | Целое число `1` |
| `key_id` | Несекретный ID записи с ключом шифрования в системном хранилище |
| `encrypted_seed` | Результат `identity.EncryptSeed`, закодированный стандартным base64 |

ID содержит 1–128 ASCII-букв, цифр, `_` или `-`. Это стабильная ссылка, а не ник.
Правила ID определены в `identity` и используются обоими адаптерами хранения.
Версия 1 фиксирует 60 байт шифротекста: 12 байт nonce, 32 байта зашифрованного
seed и 16 байт тега AES-256-GCM. Ключ шифрования в файл не входит.

`Create(keyID, encryptedSeed)` принимает готовый шифротекст; `Load()` возвращает
ID и отдельный срез шифротекста. Адаптер проверяет формат, но не может определить
подлинность данных без ключа. Это задача `identity.DecryptSeed`.

## Запись и чтение

Используется та же схема публикации, что у `profilefile`: временный файл рядом
с целевым, полная запись, `Sync`, закрытие и `os.Link`. Существующий путь не
заменяется, в том числе при конкурентном создании или повреждённом JSON.
Временный файл удаляется при штатном завершении операции, включая ошибки.
При аварийном завершении процесса временный файл может остаться.

Новые каталоги создаются с режимом `0700`, файлы — `0600` на Unix. Это не
настройка ACL на Windows. Требуется файловая система с жёсткими ссылками;
запасного способа публикации нет. Каталог отдельно не синхронизируется:
сохранность записи при отключении питания пока не гарантируется.

Загрузка ограничена 4 КиБ и принимает обычные файлы. Символические ссылки
при чтении разрешаются стандартными `os.Stat`/`os.Open`; создание не заменяет
существующую ссылку. Проверяются версия, ID, base64 и длина шифротекста.
Неизвестные поля и данные после JSON отклоняются. Ошибки разбора не содержат
входные данные. Отсутствие файла, ошибка доступа и неверный формат различаются.

## Последствия

Файл не является самостоятельной переносимой резервной копией: для расшифровки
нужна запись системного хранилища. Создание ключа, согласование с файлом профиля
и восстановление после частичного сбоя будут реализованы в сценарии приложения.
