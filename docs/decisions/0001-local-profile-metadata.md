# 0001 Хранение метаданных локального профиля

Статус: принято для первого этапа; жизненный цикл и формат профиля расширены
в [ADR 0003](0003-profile-identity-lifecycle.md). Ниже сохранено исходное решение
для версии `1`, которая остаётся доступной для чтения и явного обновления.

## Контекст

Первому рабочему сценарию нужны только ник и время создания. Ключи, контакты
и история ещё не реализованы. Нужен небольшой формат без внешних зависимостей,
который не привязывает правила профиля к интерфейсу или базе данных.

## Решение

Метаданные одного профиля сохраняются в `profile.json` с полями `version`,
`nickname` и `created_at`. Текущая версия — `1`, время записывается в UTC.
Приватные ключи в этот формат не входят. SQLite остаётся в плане для контактов,
истории и очереди сообщений.

Правила принадлежат `identity`, создание и загрузка — `app.Profiles`, формат
файла и операции с ним — `storage/profilefile`. Потребитель `app` определяет
небольшой интерфейс `ProfileStore` с операциями `Create` и `Load`.

По умолчанию используется `os.UserConfigDir()/shadowtalk`. CLI позволяет явно
выбрать другой каталог через `--profile-dir`. Чтение не создаёт каталогов.
Конфигурационный каталог используется для метаданных; расположение будущей
базы сообщений будет определено вместе с её реализацией.

## Запись и чтение

Новый файл сначала полностью записывается во временный файл в том же каталоге.
После `Sync` и закрытия он публикуется через `os.Link`. Операция отказывает,
если целевой путь уже занят. Существующий профиль не заменяется даже при двух
одновременных попытках создания. Читатель не видит промежуточно записанный JSON.
После операции временный файл удаляется.

Каталог должен находиться на файловой системе с поддержкой жёстких ссылок.
Если ссылки не поддерживаются, создание завершается ошибкой; небезопасного
перехода к записи поверх существующего файла нет. Защита от внезапного
отключения питания этим решением не гарантируется: каталог отдельно не синхронизируется.

Загрузка ограничена 4 КиБ, проверяет версию, обязательные данные, правила ника
и время создания. Неизвестные поля и лишние данные отклоняются. При ошибке
файл сохраняется без изменений. Миграций между версиями пока нет.

## Последствия

Изменение интерфейса не требует переписывать хранение, а замена хранилища
не требует менять правила ника. Будущую защиту ключей нужно реализовать
отдельно; права доступа к JSON не являются шифрованием.

Проверяются повторная загрузка, отказ от перезаписи, конкурентное создание,
невалидные и повреждённые записи, ограничения размера и ошибки CLI.
