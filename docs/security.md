# Требования к защите данных

Это требования к будущей реализации, а не заявление о достигнутой защите.

`profile.json` версии 2 содержит ник, время создания и публичный Ed25519-ключ;
файл не зашифрован. Версия 1 с метаданными без ключей поддерживается для чтения
и явного `profile upgrade`. Новые каталоги и файлы создаются с режимами `0700`
и `0600` на Unix. Эти режимы не заменяют защиту ключей и настройку ACL на Windows.
`create` не заменяет существующий профиль. `upgrade` обновляет только старые
метаданные с теми же ником и датой. Повреждённая идентичность не заменяется новой.
В `identity` доступны генерация и восстановление Ed25519-ключей
из seed в памяти. Seed возвращается отдельной копией и позволяет восстановить
приватный ключ. CLI использует эти операции через `app.Profiles`; ключи шифрования
и seed в его вывод не попадают. Отпечаток — полный SHA-256 публичного ключа.

Шифрование seed в памяти использует AES-256-GCM из стандартной библиотеки Go
с автоматически создаваемым случайным nonce. Функции принимают отдельный
случайный ключ длиной 32 байта; это не пароль и не seed. Для привязки шифротекста
к назначению используется аутентифицируемая метка `ShadowTalk/identity-seed/v1`.
Неверный ключ или повреждённые данные не возвращают открытый seed.
Для отдельного ключа шифрования реализован адаптер `storage/keyring` на базе
`go-keyring`. Он хранит 32 байта в системном хранилище секретов; base64 служит
только текстовым представлением, защиту записи обеспечивает ОС. Отсутствие записи,
ошибка доступа и повреждённое значение различаются. Ошибки адаптера не содержат
ключ или исходный текст ошибки внешней библиотеки. Запасного хранения в обычном
файле нет. При ошибке проверки после `Set` запись уже могла произойти.
CLI использует адаптер для создания и загрузки профиля. На macOS/Windows/Linux
необходимо доступное системное хранилище; ОС может показать диалог разблокировки.

`Delete(id)` удаляет только указанную запись в пространстве ключей ShadowTalk.
Неверный ID отклоняется до доступа к хранилищу. Ошибка удаления или проверки
не раскрывает данные записи и не гарантирует, что ключ остался в хранилище.
Вызывающий код должен удалять только ключ, который больше не нужен для
расшифровки сохранённого seed. При ошибке `Set` сценарий удаляет только свой
новый ключ, до публикации seed. После ошибки публикации ключ сохраняется для `recover`.

`storage/seedfile` сохраняет только ID ключа и уже зашифрованный seed в отдельном
файле `identity-seed.json`. В нём нет открытого seed или ключа шифрования.
Адаптер проверяет размер и формат записи; целостность шифротекста проверяется
при вызове `identity.DecryptSeed` с ключом из хранилища ОС. Чтение повреждённого
файла не исправляет и не удаляет его. Запись не заменяет существующий файл.
Чтение файла, получение ключа и расшифровка объединены в `app.IdentityLoader`.
При отсутствии данных, отказе доступа или ошибке расшифровки он возвращает
пустую пару ключей и ошибку; новая идентичность автоматически не создаётся.
Полученный от хранилища буфер ключа и временный расшифрованный seed очищаются
после использования. Это не гарантирует удаления всех внутренних копий из памяти Go.
`Profiles.Load` также сравнивает восстановленный публичный ключ с `profile.json`.
Подмена шифротекста и ключа другой валидной парой при неизменных метаданных
отклоняется. Это не защита от полного контроля над учётной записью ОС.

Создание и обновление сериализуются блокировкой ОС. Журнал записывается до ключа
и содержит только публичные данные и шифротекст. `profile recover` продолжает
ту же идентичность; при отсутствии ключа отмена допустима только до публикации
файлов идентичности. Потеря ключа завершённого профиля не запускает регенерацию.
Восстановление после завершения процесса проверено; гарантии при отказе диска
или отключении питания не заявляются. Копии файлов без записи хранилища ОС
недостаточно для переноса или резервного восстановления.

- Приватные ключи остаются на устройстве и не входят в приглашения.
- Ключ собеседника проверяется при соединении. Изменение известного ключа
  требует отдельного подтверждения пользователя.
- Ник не доказывает личность человека. Для первого знакомства нужен способ
  сверки отпечатков ключей по доверенному каналу.
- Приглашения имеют срок действия, отзываются и допускают одно принятие.
- Секреты приглашений и содержимое переписки не попадают в журналы.
- Отказ Tor не приводит к автоматическому прямому соединению в обход Tor.
- Внешние данные проверяются по формату и размеру до обработки; текст
  сообщений отображается без выполнения управляющих последовательностей терминала.

Формат переносимой зашифрованной резервной копии ещё предстоит выбрать.
До сетевого обмена — описать первое доверие,
проверку ключей и ограничения входящих запросов. Tor не защищает от доступа
к разблокированному устройству или от разглашения сообщений собеседником.
